1. WHY COMPLEXITY ANALYSIS?
================================================================================

INTUITION
---------
Two programs can solve the same problem but one takes 1 second
and the other takes 10 years on large input. Complexity analysis
helps us predict performance WITHOUT running the code.

Example:
- Linear search on 1 million items: ~1,000,000 operations
- Binary search on 1 million items: ~20 operations
- Same result, vastly different speed.

================================================================================
2. BIG-O NOTATION (Upper Bound)
================================================================================

DEFINITION
----------
f(n) = O(g(n)) if there exist constants c > 0 and n₀ such that
f(n) ≤ c × g(n) for all n ≥ n₀

Intuitively: "In the WORST case, the algorithm grows no faster than g(n)."

COMMON COMPLEXITIES (Best to Worst)
------------------------------------
O(1)          Constant          — hash lookup, array access
O(log n)      Logarithmic       — binary search
O(n)          Linear            — single loop
O(n log n)    Linearithmic      — merge sort, heap sort
O(n²)         Quadratic         — nested loops
O(n³)         Cubic             — triple nested loops
O(2ⁿ)        Exponential       — recursive fibonacci
O(n!)         Factorial         — brute force permutations

VISUAL GROWTH (n = 1000):
O(1)       = 1
O(log n)   = 10
O(n)       = 1,000
O(n log n) = 10,000
O(n²)      = 1,000,000
O(n³)      = 1,000,000,000
O(2ⁿ)      = ∞ (impossible)
O(n!)      = ∞ (impossible)

================================================================================
3. BIG-OMEGA (Lower Bound) & BIG-THETA (Tight Bound)
================================================================================

BIG-OMEGA: Ω(g(n))
  "In the BEST case, the algorithm grows at least as fast as g(n)."
  Linear search: Ω(1) — found on first check

BIG-THETA: Θ(g(n))
  "The algorithm grows EXACTLY as g(n) in both best and worst cases."
  Used when best and worst case have same growth rate.

================================================================================
4. HOW TO ANALYZE COMPLEXITY
================================================================================

RULE 1: Drop constants
  O(2n) → O(n)
  O(n/2) → O(n)
  O(100) → O(1)

RULE 2: Drop lower-order terms
  O(n² + n) → O(n²)
  O(n³ + n² + n) → O(n³)

RULE 3: Different inputs → different variables
  Two loops over different arrays:
  O(a + b), NOT O(n)

  Two nested loops over different arrays:
  O(a × b), NOT O(n²)

EXAMPLES
--------
# Constant
def get_first(arr):
    return arr[0]  # O(1)

# Linear
def find_max(arr):
    max_val = arr[0]
    for x in arr:       # O(n)
        if x > max_val:
            max_val = x
    return max_val

# Quadratic
def has_duplicates(arr):
    for i in range(len(arr)):          # O(n)
        for j in range(i+1, len(arr)): # O(n)
            if arr[i] == arr[j]:
                return True
    return False                        # O(n²)

# Logarithmic
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:                      # O(log n)
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

# Linearithmic (merge sort)
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])     # T(n/2)
    right = merge_sort(arr[mid:])    # T(n/2)
    return merge(left, right)        # O(n)
# T(n) = 2T(n/2) + O(n) → O(n log n)

5. SPACE COMPLEXITY
================================================================================

Space complexity = total memory used by the algorithm.

SPACE ANALYSIS
--------------
O(1) — in-place algorithm (only variables)
O(n) — creating a copy of the array
O(n²) — creating a 2D array of size n×n
O(log n) — binary search (recursion stack)

Examples:
def reverse_in_place(arr):       # O(1) space
    left, right = 0, len(arr)-1
    while left < right:
        arr[left], arr[right] = arr[right], arr[left]
        left += 1; right -= 1

def reverse_copy(arr):           # O(n) space
    return arr[::-1]

================================================================================
6. RECURRENCE RELATIONS
================================================================================

A recurrence defines T(n) in terms of smaller inputs.

COMMON RECURRENCES
------------------
T(n) = T(n-1) + O(1)     → O(n)        (linear recursion)
T(n) = T(n-1) + O(n)     → O(n²)       (selection sort)
T(n) = 2T(n/2) + O(1)    → O(n)        (perfect binary tree)
T(n) = 2T(n/2) + O(n)    → O(n log n)  (merge sort)
T(n) = 2T(n/2) + O(n²)   → O(n²)       (some divide & conquer)

================================================================================
7. MASTER THEORETUM
================================================================================

For recurrences of the form:
  T(n) = aT(n/b) + O(nᵈ)

where a ≥ 1, b > 1, d ≥ 0:

Case 1: if d < log_b(a)  → T(n) = O(n^(log_b(a)))
Case 2: if d = log_b(a)  → T(n) = O(nᵈ × log n)
Case 3: if d > log_b(a)  → T(n) = O(nᵈ)

EXAMPLES
--------
Merge sort: T(n) = 2T(n/2) + O(n)
  a=2, b=2, d=1 → log₂(2) = 1 = d → Case 2 → O(n log n) ✓

Binary search: T(n) = T(n/2) + O(1)
  a=1, b=2, d=0 → log₂(1) = 0 = d → Case 2 → O(log n) ✓

================================================================================
8. AMORTIZED ANALYSIS
================================================================================

Some operations are occasionally expensive but cheap on average.

Example: Dynamic array (Python list) append
- Most appends: O(1)
- Occasionally: O(n) when array needs to resize
- Amortized: O(1) per append

9. PRACTICE PROBLEMS
================================================================================

Q1: What is the time complexity of this code?
    for i in range(n):
        for j in range(n):
            print(i, j)
    Answer: O(n²)

Q2: What is the time complexity?
    i = 1
    while i < n:
        i = i * 2
    Answer: O(log n)

Q3: What is the time complexity?
    for i in range(n):
        for j in range(i):
            print(i, j)
    Answer: O(n²) — sum of 0+1+2+...+(n-1) = n(n-1)/2

Q4: What is the space complexity?
    def fib(n):
        if n <= 1: return n
        return fib(n-1) + fib(n-2)
    Answer: O(n) space (recursion stack), O(2ⁿ) time

Q5: What is the time complexity?
    def mystery(n):
        if n <= 1: return
        mystery(n // 2)
        mystery(n // 2)
        for i in range(n):
            print(i)
    Answer: T(n) = 2T(n/2) + O(n) → O(n log n)
