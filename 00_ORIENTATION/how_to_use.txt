2. LEARNING SEQUENCE FOR EACH MODULE
================================================================================

Follow this sequence for EVERY module:

STEP 1: READ THE OVERVIEW
    Read the module README.md
    Understand: What you will learn, Why it matters, Prerequisites

STEP 2: STUDY THE THEORY
    Read all notes/ files in order
    Take notes on key concepts
    Don't skip the "Why this exists" sections

STEP 3: STUDY THE MATHEMATICS
    Read math/ files
    Work through numerical examples BY HAND
    Understand every formula and symbol

STEP 4: STUDY THE DIAGRAMS
    Look at diagrams/ files
    Connect visual representations to the theory
    Create your own sketches if helpful

STEP 5: RUN THE CODE
    Open code/ files in Jupyter or your editor
    Run every code example
    Modify parameters and observe changes
    Experiment freely

STEP 6: COMPLETE EXERCISES
    Start with beginner/ exercises
    Progress to intermediate/ and advanced/
    Check answers only AFTER attempting

STEP 7: WORK THROUGH LABS
    Labs are guided, step-by-step experiments
    Complete every lab before moving on

STEP 8: BUILD THE PROJECT
    Start with Level 1 project
    Progress to Level 2 and Level 3
    Apply everything learned in the module

STEP 9: REVIEW CHEAT SHEET
    Read the module cheat sheet
    Mark concepts you're still unsure about

STEP 10: TEST YOURSELF
    Answer the interview questions
    Complete the module quiz
    Check the knowledge checkpoint

4. ACTIVE LEARNING TECHNIQUES
================================================================================

DON'T JUST READ — DO:

    1. WRITE CODE BY HAND
       Before copying code, try to write it yourself first.
       Even if you make mistakes, the process teaches you.

    2. EXPLAIN OUT LOUD
       After reading a concept, explain it out loud as if
       teaching someone else. If you can't explain it simply,
       you don't understand it well enough.

    3. CHANGE PARAMETERS
       When you run code, don't just observe the output.
       Change values, break things, see what happens.

    4. DRAW DIAGRAMS
       For every algorithm, draw a simple diagram on paper.
       This activates visual memory and deepens understanding.

    5. CONNECT TO PREVIOUS MODULES
       Ask: "How does this relate to what I learned before?"
       Build a mental map of connections between concepts.

    6. DEBUG PURPOSEFULLY
       When code fails, READ the error message carefully.
       Don't immediately copy a fix. Understand WHY it failed.

7. WHEN YOU GET STUCK

STEP 4: Look at the code examples and compare with yours

8. PROJECT GUIDELINES
================================================================================

EVERY project must include:

    1. Problem Statement
       What problem are you solving? Why does it matter?

    2. Dataset
       What data are you using? What does each feature mean?

    3. Approach
       What algorithm/method will you use? Why?

    4. Implementation
       Clean, modular, well-commented code

    5. Evaluation
       What metrics did you use? How did the model perform?

    6. Visualization
       Key charts and graphs showing results

    7. Documentation
       README.md with clear instructions

    8. Reflection
       What went well? What would you improve?

LEVEL 1 PROJECTS:
    - Single model, small dataset, simple interface
    - Focus on understanding the basics

LEVEL 2 PROJECTS:
    - Multiple models, real dataset, preprocessing pipeline
    - Focus on engineering practice

LEVEL 3 PROJECTS:
    - Production-style: API, database, testing, deployment
    - Focus on real-world systems
