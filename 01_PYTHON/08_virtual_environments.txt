## Why You Need It
Different ML projects often require different versions of libraries.
Virtual environments keep each project's dependencies isolated, preventing
version conflicts between projects.

================================================================================
1. WHY VIRTUAL ENVIRONMENTS?
================================================================================

PROBLEM:
    Project A needs: numpy==1.21.0
    Project B needs: numpy==1.24.0

    Without venvs, only one version can be installed globally.
    Installing for one project breaks the other.

SOLUTION: Virtual environments
    Each project gets its own isolated Python environment
    with its own installed packages.

    Project A venv: numpy==1.21.0, pandas==1.3.0
    Project B venv: numpy==1.24.0, pandas==2.0.0

    They don't interfere with each other.

================================================================================
2. CREATING A VIRTUAL ENVIRONMENT
================================================================================

CREATE:
    python -m venv ml_course_env

    This creates a folder 'ml_course_env/' containing:
    - bin/ or Scripts/ (executables)
    - lib/ (installed packages)
    - pyvenv.cfg (configuration)

ACTIVATE:

    WINDOWS (Command Prompt):
        ml_course_env\Scripts\activate

    WINDOWS (PowerShell):
        ml_course_env\Scripts\Activate.ps1

    MAC/LINUX:
        source ml_course_env/bin/activate

    You'll see (ml_course_env) in your terminal prompt when activated.

DEACTIVATE:
    deactivate

================================================================================
3. INSTALLING PACKAGES WITH PIP
================================================================================

INSTALL:
    pip install numpy
    pip install pandas matplotlib seaborn
    pip install scikit-learn

SPECIFY VERSION:
    pip install numpy==1.24.3
    pip install "numpy>=1.24,<2.0"

UPGRADE:
    pip install --upgrade numpy

UNINSTALL:
    pip uninstall numpy

LIST INSTALLED:
    pip list

SHOW PACKAGE INFO:
    pip show numpy

SEARCH:
    pip search numpy    # May be disabled on PyPI

================================================================================
4. REQUIREMENTS.TXT
================================================================================

SAVE DEPENDENCIES:
    pip freeze > requirements.txt

    This creates a file like:
    numpy==1.24.3
    pandas==2.0.3
    scikit-learn==1.3.0
    matplotlib==3.7.2

INSTALL FROM FILE:
    pip install -r requirements.txt

BEST PRACTICES:
    - Always create requirements.txt for your projects
    - Include ALL dependencies (not just main ones)
    - Pin exact versions for reproducibility
    - Update requirements.txt when adding new packages

EXAMPLE REQUIREMENTS.TXT FOR ML PROJECT:
    # Core
    numpy==1.24.3
    pandas==2.0.3
    scipy==1.11.4

    # ML
    scikit-learn==1.3.2
    xgboost==2.0.3

    # Visualization
    matplotlib==3.8.2
    seaborn==0.13.1

    # Deep Learning (install separately)
    # torch==2.1.0
    # tensorflow==2.15.0

    # API
    fastapi==0.104.1
    uvicorn==0.24.0

    # Utilities
    python-dotenv==1.0.0

================================================================================
5. PROJECT SETUP TEMPLATE
================================================================================

FOR EVERY NEW ML PROJECT:

    1. Create project directory
       mkdir my_ml_project
       cd my_ml_project

    2. Create virtual environment
       python -m venv venv

    3. Activate it
       source venv/bin/activate    # Mac/Linux
       venv\Scripts\activate       # Windows

    4. Create requirements.txt
       (add your dependencies)

    5. Install dependencies
       pip install -r requirements.txt

    6. Create .gitignore
       echo "venv/" >> .gitignore
       echo "__pycache__/" >> .gitignore
       echo "*.pyc" >> .gitignore
       echo ".env" >> .gitignore

    7. Initialize git
       git init

    8. Create your project structure
       mkdir data models src tests

    9. Start coding!

IMPORTANT: NEVER commit the virtual environment to Git.
    The .gitignore should include:
    venv/
    .venv/
    env/
