THE GAP BETWEEN NOTEBOOK AND PRODUCTION
----------------------------------------

- Single data file
- Manual preprocessing
- One model
- Manual evaluation
- Local execution

Production:
- Multiple data sources
- Automated pipelines
- Multiple model versions
- Continuous monitoring
- Distributed systems

2. MLOPS
================================================================================

MLOps = Machine Learning Operations

KEY PILLARS:
1. Experiment Tracking: record all experiments
2. Model Registry: version and store models
3. Pipeline Automation: automate training and deployment
4. Monitoring: track model performance in production
5. Version Control: code, data, and models

USING MLFLOW
------------
import mlflow
import mlflow.sklearn

# Track experiment
mlflow.set_experiment("my_experiment")

with mlflow.start_run():
    # Train model
    model = RandomForestClassifier(n_estimators=100)
    model.fit(X_train, y_train)

    # Log parameters
    mlflow.log_param("n_estimators", 100)

    # Log metrics
    accuracy = model.score(X_test, y_test)
    mlflow.log_metric("accuracy", accuracy)

    # Log model
    mlflow.sklearn.log_model(model, "model")

3. MONITORING
================================================================================

WHAT TO MONITOR
---------------
1. Model Performance
   - Accuracy, precision, recall over time
   - Prediction distribution

2. Data Quality
   - Missing values rate
   - Feature distribution changes
   - Schema changes

3. System Health
   - Latency (p50, p95, p99)
   - Throughput (requests per second)
   - Error rate
   - CPU/memory usage

DRIFT DETECTION
---------------
Data Drift: input data distribution changes
Concept Drift: relationship between input and target changes

# Simple drift detection
from scipy.stats import ks_2samp

# Compare recent predictions to baseline
stat, p_value = ks_2samp(baseline_predictions, recent_predictions)
if p_value < 0.05:
    alert("Data drift detected!")

4. CI/CD FOR ML
================================================================================

# .github/workflows/ml-pipeline.yml
name: ML Pipeline

on:
  push:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Run tests
        run: |
          pip install -r requirements.txt
          pytest tests/

  train:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - name: Train model
        run: python train.py
      - name: Evaluate
        run: python evaluate.py

  deploy:
    needs: train
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to cloud
        run: |
          docker build -t ml-api .
          docker push ...

6. COMMON PRODUCTION ISSUES
================================================================================

1. DATA LEAKAGE: Test data influences training
   → Fix: Proper train/test split, pipeline-based preprocessing

2. MODEL DRIFT: Model performance degrades over time
   → Fix: Regular retraining, monitoring, alerts

3. FEATURE DRIFT: Input feature distributions change
   → Fix: Monitor feature distributions, automated retraining

4. SILENT FAILURES: Model returns wrong predictions silently
   → Fix: Confidence thresholds, human review, monitoring

5. LATENCY SPIKES: Prediction latency suddenly increases
   → Fix: Auto-scaling, caching, model optimization
