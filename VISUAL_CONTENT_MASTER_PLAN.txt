1. VISUAL GRADING (difficulty levels)
--------------------------------------------------------------------------------
LEVEL 0  Absolute beginner   - 3 boxes, plain words, one direction of flow
LEVEL 1  Beginner            - concept image + one simple pipeline
LEVEL 2  Intermediate        - labeled stages, small math annotations
LEVEL 3  Advanced            - full architecture, tensor shapes on the boxes
LEVEL 4  Professional        - real component names, latency/cost annotations
LEVEL 5  Senior engineer     - tradeoff callouts, failure modes, scale notes
LEVEL 6  Expert              - memory/latency math, GPU execution notes
LEVEL 7  Research            - ablations, parameter sweeps, benchmark curves

RULE: beginner visuals must NOT look like paper figures; expert topics are
allowed full technical density.

--------------------------------------------------------------------------------
2. THE THREE-LEVEL VISUAL SYSTEM (one concept -> three figures)
--------------------------------------------------------------------------------
For every difficult concept produce THREE panels:
  LEVEL 1 - INTUITION : what it is, in the world.        (no jargon)
  LEVEL 2 - TECHNICAL : internal architecture/mechanics. (named components)
  LEVEL 3 - IMPLEMENTATION: code + tensors + math flow.  (shapes on boxes)
Example - attention:
  L1 "tokens look at other tokens"         (arrows between words)
  L2 Q -> K -> attention matrix -> V       (block diagram)
  L3 QK^T / sqrt(d_k) -> softmax -> V      (matrices with dims labeled)

4. SHARED VISUAL LANGUAGE (consistency rules - apply to EVERY panel)
--------------------------------------------------------------------------------
SYMBOLS
  [DOC/BOX]  rounded rect = component/service          color-coded by kind:
             blue #1565c0 = data/inference pipeline     green #2e7d32 = storage
             amber #b26a00 = query/user input           purple #5e35b1 = model/
             red   #b02a37 = failure/risk               compute
  ARROW      solid  ->   data/control flow (label = what moves)
             dashed -->  feedback/update loop
  tensor     boxes annotated with real shapes: (B, T, d), (T, T), (d_k)
  time       flows left -> right or top -> bottom ONLY (never mixed in one fig)

NOMENCLATURE (consistent everywhere)
  embedding = dense vector in semantic space   RAG = retrieval + context +
             generation (never just "vector DB")
  RAG lifecycle = INGEST (load->parse->clean->chunk->embed->index) THEN QUERY
             (process->transform->retrieve->rerank->prompt->generate->cite)

MATH ACCURACY
  verify every equation before rendering. Canonical forms used everywhere:
    cosine sim = (a.b) / (|a||b|)                 attention = softmax(QK^T/sqrt d_k) V
    BM25 = IDF * (f(k1+1)) / (f + k1(1-b+b|D|/avgdl))   softmax = e^z / sum e^z
    P(token) = softmax(logits / T)                MSE = (1/n) sum (y - yhat)^2

CODE ACCURACY
  never draw invented APIs. LangChain/LangGraph panels use CURRENT stable
  concepts (Runnable/LCEL, StateGraph, nodes/edges/state); PyTorch panels use
  tensors/autograd/nn.Module; Hugging Face panels use current transformers APIs.
