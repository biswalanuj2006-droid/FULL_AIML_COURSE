1. WHY SPARK?
================================================================================

PROBLEM: Pandas loads everything into memory.
- 10GB CSV → pandas cannot handle
- 100GB dataset → impossible with single machine

SPARK SOLUTION:
- Distributed processing across cluster
- Lazy evaluation (optimizes execution plan)
- In-memory computation (100x faster than MapReduce)
- Unified engine: SQL + Streaming + ML + Graphs

WHEN TO USE:
- Dataset > memory (10GB+)
- Need distributed processing
- Real-time streaming analytics
- Distributed ML training

================================================================================
2. SPARK ARCHITECTURE
================================================================================

┌─────────────────────────────────────────┐
│              DRIVER PROGRAM             │
│         (PySpark application)           │
└──────────────────┬──────────────────────┘
                   │
         ┌─────────▼─────────┐
         │  SPARK CONTEXT     │
         │  (Connection to    │
         │   cluster)         │
         └─────────┬─────────┘
                   │
    ┌──────────────┼──────────────┐
    ▼              ▼              ▼
┌────────┐   ┌────────┐   ┌────────┐
│EXECUTOR│   │EXECUTOR│   │EXECUTOR│
│Worker 1│   │Worker 2│   │Worker 3│
└────────┘   └────────┘   └────────┘

KEY CONCEPTS:
- DRIVER: Master process, coordinates work
- EXECUTOR: Worker processes, execute tasks
- RDD: Resilient Distributed Dataset (basic abstraction)
- DataFrame: Distributed table (high-level API)
- DAG: Directed Acyclic Graph (execution plan)

# Read from Kafka
stream_df = spark.readStream \
    .format("kafka") \
    .option("kafka.bootstrap.servers", "localhost:9092") \
    .option("subscribe", "transactions") \
    .load()

# Process stream
from pyspark.sql.functions import from_json, col
from pyspark.sql.types import StructType, StringType, DoubleType

schema = StructType([
    StructField("user_id", StringType()),
    StructField("amount", DoubleType())
])

parsed = stream_df.select(
    from_json(col("value").cast("string"), schema).alias("data")
).select("data.*")

# Write stream
query = parsed.writeStream \
    .outputMode("append") \
    .format("console") \
    .start()

query.awaitTermination()

8. PERFORMANCE OPTIMIZATION
================================================================================

KEY OPTIMIZATIONS:
1. Partition data properly
   df = df.repartition(200, "key_column")

2. Cache frequently used DataFrames
   df.cache()  # or df.persist()
   
3. Avoid shuffles
   df.join(df2, "key")  # better than df.join(df2, df1.key == df2.key)

4. Use broadcast joins for small tables
   from pyspark.sql.functions import broadcast
   df_large.join(broadcast(df_small), "key")

5. Tune shuffle partitions
   spark.conf.set("spark.sql.shuffle.partitions", "200")

6. Use Parquet format (columnar, compressed)
   df.write.parquet("output.parquet")

7. Avoid UDFs when possible (use built-in functions)
   # BAD: udf(lambda x: x.upper())
   # GOOD: F.upper(F.col("name"))

================================================================================
9. COMMON MISTAKES
================================================================================

1. Collecting large DataFrames to driver (df.collect())
   RIGHT: Use df.show() or write to storage

2. Not caching DataFrames used multiple times
   RIGHT: df.cache() before multiple operations

3. Too many shuffle partitions
   RIGHT: Tune based on data size

4. Using Python UDFs instead of Spark SQL functions
   RIGHT: Prefer built-in functions

5. Not using broadcast joins for small tables
   RIGHT: broadcast(small_df)
