1. WHAT ANOMALY DETECTION IS
================================================================================

INTUITION
A security camera watching a warehouse: every night the same motion
pattern, except one night. The goal is not to describe "normal" perfectly -
it is to FLAG what does not fit, so a human (or rule) can act.

DEFINITION
Anomaly detection = identify observations that deviate from the data's
normal behavior so much that they are suspected of being generated by a
different process.

It is USUALLY unsupervised: you have mostly-normal data and want to flag
the rare deviations (fraud is ~0.1% of transactions; you cannot label it
well in advance).

WHERE USED
- Fraud detection (cards, claims, ad clicks)
- Network intrusion detection
- Industrial / predictive maintenance (sensor faults)
- Manufacturing defect detection
- Server / app monitoring (NOC alerts)
- Medical monitoring (ICU vitals)
- Data cleaning (find bad records before modeling)

KEY DIFFERENCE FROM CLASSIFICATION
Classification learns the boundary between KNOWN classes. Anomaly
detection must work when anomalies are rare, heterogeneous, and novel
(new attack today was unseen yesterday). That is why density/statistical
methods dominate: they model NORMALITY.

================================================================================
2. ANOMALY TYPES
================================================================================

A. POINT anomaly   - one observation is extreme by itself.
   Example: a credit card charge of $90,000 when the user spends ~$100.

B. CONTEXTUAL anomaly - normal value, wrong context.
   Example: 25C on a summer afternoon is normal; 25C at 3 AM in winter
   is strange. Context = time, location, season, group.

C. COLLECTIVE anomaly - individual points are normal, the SEQUENCE/group
   is not.
   Example: a heartbeat ECG - each beat looks fine but the rhythm pattern
   between them is pathological.

Method choice depends on type: point methods (z-score, iForest) for A;
context methods (residuals against expected context, time models) for B;
sequence/window methods for C.

================================================================================
3. STATISTICAL METHODS (UNIVARIATE)
================================================================================

Z-SCORE
  z_i = (x_i - mean) / std
  Flag if |z_i| > threshold (commonly 3).
  ASSUMPTION: data roughly Gaussian, no strong skew, few outliers
  (mean/std are not robust - a single huge outlier inflates std and
  HIDES other outliers - masking).

NUMERICAL EXAMPLE
  Data: [10, 12, 11, 13, 10, 200]
  mean = 256/6 = 42.67, std ~ 74.7
  z(200) = (200-42.67)/74.7 = 2.11  -> NOT flagged at 3!
  The outlier pulled mean up and std up: masking. This is exactly why
  plain z-score fails on dirty data.

ROBUST Z (MEDIAN + MAD)
  Modified z = 0.6745 * (x_i - median) / MAD
  where MAD = median(|x_i - median|) and 0.6745 makes MAD consistent
  for Gaussians (E[MAD] = 0.6745*sigma).
  Example data: median = 11.5, MAD = 1.5
  modz(200) = 0.6745*(200-11.5)/1.5 = 84.8 -> flagged. Robust wins.

IQR RULE (BOXPLOT RULE)
  Flag if x < Q1 - 1.5*IQR or x > Q3 + 1.5*IQR.
  Distribution-free-ish, robust to skew for flagging tails; the 1.5 is a
  convention tuned for Gaussian tails (about 0.7% flagged).

When to use: quick screening, single columns, interpretable rules.
When NOT: multivariate interactions (anomalies that are normal in each
column alone), high-dim data, no distributional assumptions hold.

================================================================================
4. MULTIVARIATE: MAHALANOBIS + ROBUST COVARIANCE
================================================================================

Univariate methods miss the point that is normal per-column but abnormal
in COMBINATION. Example: age 30 and income 5M are each plausible; the pair
is suspicious.

MAHALANOBIS DISTANCE (generalizes z-score to vectors)
  D^2(x) = (x - mu)^T Sigma^{-1} (x - mu)
  - mu: mean vector, Sigma: covariance matrix
  - Accounts for correlation: distance along the data's natural
    directions, not raw Euclidean
  - For 1D this reduces to z^2.

  Under Gaussian data, D^2 ~ chi-squared with d degrees of freedom, so a
  principled threshold: flag D^2 > chi2.ppf(0.99, d).

PROBLEM: mean and covariance are NOT robust - outliers contaminate them
(the masking problem again).

FIX - ROBUST COVARIANCE (Minimum Covariance Determinant, MCD)
  sklearn.covariance.EllipticEnvelope fits the covariance on the subset
  (h points) with the smallest determinant, then scores by Mahalanobis
  distance. Robust to up to ~n - h contamination.

  from sklearn.covariance import EllipticEnvelope
  ee = EllipticEnvelope(contamination=0.01)   # expected anomaly share
  ee.fit(X)
  preds = ee.predict(X)      # 1 normal, -1 anomaly
  scores = ee.score_samples(X)   # negative Mahalanobis-like: lower = weirder

ASSUMPTION: data is approximately a single multivariate Gaussian.
When data is multimodal, GMM (module 11_CLUSTERING) with a log-likelihood
threshold is the natural upgrade.

================================================================================
5. DENSITY & DISTANCE: KNN AND LOF
================================================================================

IDEA: anomalies live in low-density regions.

KNN-DISTANCE SCORE
  anomaly_score(x) = distance to its k-th nearest neighbor
  (or mean distance to k neighbors). Higher = more isolated.
  Simple, no distributional assumption beyond "distance is meaningful"
  (SCALE YOUR FEATURES first!).

LOCAL OUTLIER FACTOR (LOF) - sklearn.neighbors.LocalOutlierFactor
  Refines kNN: compares the local density around x with the local density
  around its neighbors. LOF > 1 means x is less dense than its neighbors
  -> local outlier.

  Definitions:
  - reachability_distance_k(x, y) = max(k-distance(y), dist(x, y))
  - local reachability density lrd(x) = 1 / mean(reach-dist of x's
    neighbors)
  - LOF(x) = mean(lrd of x's neighbors) / lrd(x)

  WHY REACHABILITY: stabilizes density estimates for points inside
  clusters (avoids divide-by-tiny issues).

  lof = LocalOutlierFactor(n_neighbors=20, contamination=0.01)
  preds = lof.fit_predict(X)     # -1 = outlier
  scores = -lof.negative_outlier_factor_

STRENGTH vs kNN-score: LOF is LOCAL - it detects outliers even when
different regions have very different densities (global kNN would flag
points of a sparse-but-legit cluster).

WEAKNESS: n_neighbors tuning; poor in very high dimensions (distances
concentrate); O(n^2) brute force (approx via kd-tree/batch for big data).

================================================================================
6. ISOLATION FOREST  (sklearn.ensemble.IsolationForest)
================================================================================

RADICALLY DIFFERENT IDEA: do not model normality - ISOLATE anomalies.
Anomalies are few and different, so they are EASY to isolate: a random
decision tree that keeps splitting on random feature/threshold will
separate an anomaly from the rest in FEW splits.

ALGORITHM
  For each of n_estimators trees:
    1. Sample max_samples points (default 256).
    2. Build a random tree: pick random feature + split value between
       min and max, recurse until every point is alone or depth limit.
    3. Record path length h(x) = number of edges to isolate x.
  Average h(x) over trees: E[h(x)].

SCORING
  c(n) = 2*(ln(n-1) + 0.5772) - 2*(n-1)/n     (average path length of an
  unsuccessful BST search in a tree of n points - normalization)
  s(x, n) = 2^( -E[h(x)] / c(n) )

  Interpretation:
  - s -> 1: very likely anomaly (very short path - easy to isolate)
  - s -> 0.5: average (indistinguishable)
  - s -> 0: very likely normal (long path - deep in the data)

  sklearn exposes decision_function = -E[h(x)] (lower = more anomalous);
  convert to s if you want the 0-1 scale.

  from sklearn.ensemble import IsolationForest
  iso = IsolationForest(n_estimators=100, max_samples=256,
                        contamination=0.01, random_state=42)
  iso.fit(X)
  preds = iso.predict(X)          # 1 normal, -1 anomaly
  scores = iso.decision_function(X)   # lower = more anomalous

STRENGTHS
  - No distributional/density assumption; works on mixed dtypes (with
    proper encoding)
  - Linear-ish scaling, parallel trees, handles high dimensions
    (subsampling means the tree never sees all points)
  - Widely effective default for tabular fraud/NOC data

WEAKNESSES
  - Random splits can miss anomalies that hide along a feature where
    normal data varies a lot
  - contamination is a guess that changes the threshold
  - Path length depends on sampling; very small anomalies with few
    samples can be missed (the classic "needle in a haystack")

FROM SCRATCH (concept; implement in practice)
  Build 1 random tree: recursively split, measure depth to isolate each
  point, average over ~50 trees, apply s(x,n) formula. Parity-check vs
  sklearn's decision_function ranking (not raw values - scales differ).

7. ONE-CLASS SVM  (sklearn.svm.OneClassSVM)
================================================================================

Learns a boundary around the normal data in kernel space (nu-SVM).
  - nu roughly bounds the fraction of anomalies (nu in (0,1]).
  - Kernel choice matters: RBF for nonlinear normal regions.

  from sklearn.svm import OneClassSVM
  ocsvm = OneClassSVM(kernel="rbf", gamma="scale", nu=0.01)
  ocsvm.fit(X)
  preds = ocsvm.predict(X)     # 1 normal, -1 anomaly

GOOD: flexible boundary, works when normal data is nonlinear.
BAD: no score calibration (just sign of decision); VERY sensitive to
gamma/nu; slow on large data (O(n^2)-ish); does not scale to 100k+ rows
well. Often weaker than Isolation Forest on large tabular data.

================================================================================
8. AUTOENCODER RECONSTRUCTION ERROR (concept -> DL module 19/20)
================================================================================

Train an autoencoder on (mostly) NORMAL data: input -> compress -> rebuild.
- Normal points: reconstruct well (small error).
- Anomalies: patterns never seen, reconstruction error is large.

  error(x) = || x - decoder(encoder(x)) ||^2   (or MSE per sample)
  Flag if error > threshold (fit threshold on a clean validation set).

Why it matters here: feature engineering is automatic (learned), and it
extends to images/sequences where z-score/IF do not apply (defect images,
ECG, logs). Danger: autoencoders can memorize anomalies if contamination
is high - keep training data clean.

================================================================================
9. TIME-SERIES ANOMALY DETECTION (link to module 16)
================================================================================

Contextual anomalies dominate. Standard approaches:
  a) Rolling statistics: flag |x_t - rolling_mean| > k * rolling_std
     (seasonality destroys this - a daily series with weekly pattern
     needs seasonal windows or decomposition first).
  b) Residual method: fit expected value (ARIMA, STL decomposition,
     Prophet-style, or a supervised forecaster) and flag large
     residuals. Best when you can model the seasonality.
  c) Difference between spike and regime change: a point 6 sigma above
     the mean can be a spike OR a step change. Use change-point tests
     (ruptures library) for regimes; rolling methods for spikes.
  d) Collective anomalies: window-level features (variance, entropy of
     the window) scored with IF/LOF.

RULE: never apply point-anomaly methods to raw seasonal data without
detrending/deseasonalizing, or every seasonal peak will "anomaly".

================================================================================
10. THRESHOLD SELECTION & EVALUATION WITHOUT LABELS
================================================================================

Most detectors output a SCORE; you must choose where to cut.

Threshold strategies:
  1. contamination estimate: business guess (fraud ~0.1%) -> quantile.
  2. Clean-reference set: score known-normal data, take p99/p99.9.
  3. Label a small audit set (even 100 cases) purely to TUNE the
     threshold - this is legitimate: labels only set the operating
     point, they do not train the detector.
  4. Cost-aware: flag until marginal cost of a false alert equals the
     cost of a missed anomaly.

Evaluation WITHOUT labels:
  - You cannot measure precision/recall directly. Use:
    * ranking quality on a tiny labeled audit set (PR-AUC, precision@k)
    * stability: scores of the same data with different seeds/params
    * calibration sanity: contamination fraction flagged ~= guess
  - For monitoring: measure ALERT RATE and FALSE-ALARM rate over time;
    tune until alerts are actionable (a model that never alerts is as
    broken as one that alerts constantly).

Supervised upgrade: if you later collect labels (confirmed fraud),
switch to classification (module 09) - anomaly detection is often the
first stage that collects those labels.

================================================================================
11. CHOOSING A METHOD (DECISION TABLE)
================================================================================

Situation                                  Suggested start
------------------------------------------ --------------------------------
Quick single-column screen                 robust z / IQR
Clean, single Gaussian cluster             Elliptic Envelope (MCD)
Multi-modal or clustered normal            GMM log-likelihood, LOF
Tabular, many columns, no assumptions      Isolation Forest (default)
Nonlinear normal boundary, small data      One-class SVM (RBF)
Images / sequences / learned features      Autoencoder error
Seasonal time series                        decomposition + residual/rolling
High-dim sparse (logs, events)              Isolation Forest on hashed feats

General ranking of defaults for tabular fraud/monitoring:
Isolation Forest > LOF > Elliptic Envelope > One-class SVM (size
permitting). Always compare 2-3 on the same labeled audit set if you
have one.

13. FAILURE MODES & DEBUGGING
================================================================================

Symptom                          Likely cause                   Fix
-------------------------------- ------------------------------ -----------------
Nothing flagged on dirty data    masking (mean/std polluted)    robust methods (MAD/MCD)
Everything flagged (5%+)         contamination set too high,   lower contamination;
                                 or data not scaled             scale features
Seasonal peaks all flagged       no deseasonalization           decompose first
Anomalies hide in 1 column       high-dim dilution              feature selection/IF subsample
Detector good in lab, useless    evaluation used labels from    audit-set thresholding,
  in prod                          training (leak)               monitor alert rate
Score distribution bimodal       threshold at wrong spot        fit threshold on clean set
O(n^2) blowup on 1M rows         brute-force LOF/kNN            batch/approx, IF
Autoencoder misses rare class    memorization (contamination)   keep training clean,
                                                               add noise/regularization

Debugging principle: ALWAYS look at the flagged points. If the top-20
flagged points are not "interesting" to a domain expert, your detector or
features are wrong regardless of the score.
