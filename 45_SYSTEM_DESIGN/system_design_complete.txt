2. ML PREDICTION SYSTEM ARCHITECTURE
================================================================================

                    User
                      ↓
                 Frontend
                      ↓
                 API Gateway
                      ↓
                 Backend API
                ↙     ↓      ↘
           Database   ML     Cache
                     ↓
                  Model
                     ↓
                Prediction
                     ↓
                  Logging
                     ↓

COMPONENTS
----------
- Frontend: User interface (web/mobile)
- API Gateway: Rate limiting, authentication
- Backend API: Business logic, orchestration
- ML Model: Inference service
- Database: Store predictions, user data
- Cache: Fast retrieval of common predictions
- Monitoring: Track model performance, drift

3. RECOMMENDATION SYSTEM DESIGN
================================================================================

OFFLINE PIPELINE
----------------
Data Collection → Feature Engineering → Model Training
→ Model Evaluation → Model Registry → Batch Predictions

ONLINE PIPELINE
----------------
User Request → Feature Store → Model Inference
→ Re-ranking → Response → Logging

TECHNOLOGIES
------------
- Data: Spark, Pandas
- Feature Store: Redis, Feast
- Model: XGBoost, Neural Collaborative Filtering
- Serving: FastAPI, TensorFlow Serving
- Storage: PostgreSQL, S3
- Cache: Redis

================================================================================
4. REAL-TIME ML SYSTEM DESIGN
================================================================================

EXAMPLE: FRAUD DETECTION SYSTEM

Data Flow:
Transaction → Kafka → Feature Engineering
→ ML Model (real-time) → Decision (flag/allow)
→ Alert System → Dashboard

Architecture:
- Kafka: stream transactions
- Flink/Spark Streaming: compute features
- ML Model: lightweight model for low latency
- Redis: cache recent features
- PostgreSQL: store decisions
- Dashboard: monitor alerts

Latency Requirements:
- Fraud detection: < 100ms
- Recommendation: < 500ms
- Search ranking: < 200ms

================================================================================
5. RAG SYSTEM DESIGN
================================================================================

Components:
1. Document Pipeline: Load → Clean → Chunk → Embed → Store
2. Retrieval: Query → Embed → Vector Search → Rerank
3. Generation: Context + Query → LLM → Response
4. Evaluation: Accuracy, faithfulness, relevance

Architecture:
- Document Store: PostgreSQL (metadata)
- Vector DB: Qdrant / Pinecone
- Embeddings: Sentence Transformers
- LLM: GPT-4 / Claude
- Cache: Redis (for repeated queries)
- API: FastAPI
- Frontend: React / Streamlit

================================================================================
6. DESIGN DECISIONS
================================================================================

BATCH vs REAL-TIME
-------------------
Batch: predictions generated periodically (e.g., daily recommendations)
Real-time: predictions on-demand (e.g., fraud detection)

ONLINE vs OFFLINE INFERENCE
----------------------------
Online: API call → prediction (low latency needed)
Offline: batch job → predictions stored (latency not critical)

MONITORING vs OBSERVABILITY
----------------------------
Monitoring: tracking metrics (accuracy, latency)
Observability: understanding system behavior (logs, traces, metrics)
