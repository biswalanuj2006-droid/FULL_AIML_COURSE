================================================================================
1. WHY UNCERTAINTY MATTERS
================================================================================

A point prediction y-hat hides the risk. The same prediction of "50"
means very different things if the model is sure (48-52) vs unsure
(10-90). Where uncertainty matters:
  - Medical dosing, credit limits, inventory: you act differently
    under uncertainty
  - Active learning: query where the model is most uncertain
  - Safe ML: refuse to predict far from training data
  - Monitoring: uncertainty that grows over time signals drift

Classical regression gives ONE number. Bayesian methods give a
DISTRIBUTION over the answer: P(w | data) for weights, and therefore a
distribution over predictions.

================================================================================
2. BAYES THEOREM RECAP
================================================================================

  P(w | D) = P(D | w) * P(w) / P(D)
             ^posterior  ^likelihood ^prior

  - P(w): PRIOR - what we believed about weights before seeing data
    (regularization is a prior in disguise!)
  - P(D | w): LIKELIHOOD - how well w explains the data
  - P(w | D): POSTERIOR - what we believe after data
  - P(D): evidence/normalizer (usually intractable; makes it a proper
    distribution)

MLE:   w* = argmax_w P(D | w)              (maximize likelihood)
MAP:   w* = argmax_w P(D | w) * P(w)       (add the prior)
Bayes: keep the WHOLE posterior P(w | D), not just its mode

KEY INSIGHT: Ridge regression is MAP with a Gaussian prior on w;
Lasso is MAP with a Laplace prior. Regularization you already use IS
Bayesian inference in disguise.

================================================================================
3. BAYESIAN LINEAR REGRESSION (the math, done by hand)
================================================================================

Model: y = w^T x + eps,  eps ~ N(0, sigma^2)

Prior:  w ~ N(0, sigma_p^2 I)         (Gaussian prior on weights)
Likelihood for n iid points:
  P(D | w) = prod_i N(y_i | w^T x_i, sigma^2)
           = (2 pi sigma^2)^(-n/2) exp( -sum_i (y_i - w^T x_i)^2 / (2 sigma^2) )

Because prior and likelihood are both Gaussian (CONJUGATE), the
posterior is also Gaussian and has a closed form:
  w | D ~ N(mu_w, Sigma_w)

  Sigma_w = (sigma^-2 X^T X + sigma_p^-2 I)^-1
  mu_w    = sigma^-2 Sigma_w X^T y

SYMBOLS:
  X: design matrix (n x d), rows = samples
  sigma^2: noise variance of the data
  sigma_p^2: prior variance of weights (smaller = stronger prior =
             more shrinkage toward 0 = like bigger Ridge alpha)
  mu_w: posterior mean of weights (the "best" weights)
  Sigma_w: posterior covariance of weights - THE UNCERTAINTY

Compare with Ridge closed form:
  w_ridge = (X^T X + lambda I)^-1 X^T y
With sigma_p^-2 = lambda (and sigma^2=1) they are THE SAME formula -
Bayesian regression literally contains Ridge as its MAP solution.

================================================================================
4. PREDICTIONS WITH UNCERTAINTY (POSTERIOR PREDICTIVE)
================================================================================

For a new input x*:
  y* | D ~ N(mu_w^T x*,  sigma_y^2(x*))

  mean:      m(x*) = mu_w^T x*
  variance:  v(x*) = sigma^2 + x*^T Sigma_w x*
              ^noise       ^parameter/Epistemic uncertainty

- The first term (sigma^2): irreducible noise - same even with infinite
  data.
- The second term (x*^T Sigma_w x*): grows when x* is far from the
  training data (leveraged predictions are uncertain) - this is exactly
  what classical regression hides.

This gives you prediction INTERVALS that widen outside the data cloud -
the honest behavior a point estimate lacks.

================================================================================
5. GAUSSIAN PROCESS: INTUITION FIRST
================================================================================

Bayesian linear regression puts a distribution over WEIGHTS. A Gaussian
Process puts a distribution over FUNCTIONS:

  f ~ GP(m(x), k(x, x'))

A GP is defined by:
  - m(x): mean function (often 0 after centering)
  - k(x, x'): covariance/kernel function - how much f(x) and f(x')
    correlate as a function of their inputs' distance

INTUITION: infinitely many functions pass through any finite set of
points. A GP assigns a probability to each function; the kernel encodes
what kind of functions are plausible (smooth? periodic? linear?). After
seeing data, we keep only the functions consistent with it.

WHY "PROCESS": any finite set of points (x_1..x_n), the function values
(f(x_1)..f(x_n)) are jointly Gaussian:
  f ~ MVN(m, K),  K_ij = k(x_i, x_j)

That property - "any finite marginal is Gaussian" - is the definition of
a Gaussian Process.

================================================================================
6. KERNELS = COVARIANCE FUNCTIONS
================================================================================

The kernel is the HEART of the GP. Common choices:

  RBF (squared exponential):
    k(x, x') = sigma_f^2 * exp( -||x - x'||^2 / (2 l^2) )
    - l (lengthscale): how far inputs must be before outputs decorrelate.
      Small l = wiggly functions; large l = smooth functions.
    - sigma_f^2: signal variance (vertical scale of functions)

  Periodic: k(x,x') = sigma_f^2 exp( -2 sin^2(pi (x-x')/p) / l^2 )
    - p = period; for seasonality

  Linear:  k(x,x') = x^T x'  (recovers Bayesian linear regression!)

  Mattern: like RBF but with tunable smoothness (less smooth, often
    better behaved numerically)

Kernel choice = your prior over function shape. Sum kernels to combine
behaviors (e.g., RBF + Periodic for a smooth seasonal signal).

================================================================================
7. GP REGRESSION MATHEMATICS
================================================================================

Given training (X, y) with noise sigma_n^2 and test inputs X*:

  Joint:  [ y   ] ~ MVN(0, [ K(X,X) + sigma_n^2 I    K(X, X*)     ])
          [ f*  ]          [     K(X*, X)             K(X*, X*)    ]

Posterior predictive (condition on y - the key formulas):

  mean:    mu* = K(X*, X) [K(X, X) + sigma_n^2 I]^-1 y
  cov:     Sigma* = K(X*, X*) - K(X*, X) [K(X, X) + sigma_n^2 I]^-1 K(X, X*)

SYMBOLS:
  K(X,X): n x n Gram matrix of kernel evaluations on training inputs
  K(X*,X): m x n cross-kernel matrix (test vs train)
  sigma_n^2 I: noise on observations (added to the diagonal)

Interpretation:
  - Mean: a weighted combination of training targets (like kernel
    ridge regression)
  - Diagonal of Sigma*: per-point predictive variance - uncertainty!
    It is SMALL near training points and returns to the prior variance
    far away (unless a trend kernel carries it)

NUMERICAL COST: inverting an n x n matrix -> O(n^3) training, O(n^2)
prediction. This is the fundamental GP limitation.

================================================================================
8. SKLEARN IMPLEMENTATION + WORKED STYLE
================================================================================

  import numpy as np
  from sklearn.gaussian_process import GaussianProcessRegressor
  from sklearn.gaussian_process.kernels import RBF, ConstantKernel

  X = np.linspace(0, 10, 20).reshape(-1, 1)
  y = np.sin(X).ravel() + 0.1 * np.random.default_rng(0).normal(size=20)

  kernel = ConstantKernel(1.0) * RBF(length_scale=1.0)
  gp = GaussianProcessRegressor(kernel=kernel, alpha=0.1,  # noise
                                normalize_y=True,
                                n_restarts_optimizer=5)
  gp.fit(X, y)

  Xs = np.linspace(-2, 12, 200).reshape(-1, 1)
  mu, std = gp.predict(Xs, return_std=True)

  # 95% interval: mu +/- 1.96*std
  # NOTE how std is small near training points and GROWS outside [0,10]
  # - the model knows what it does not know.

  gp.kernel_            # optimized hyperparameters (length_scale etc.)

Hyperparameter tuning: sklearn maximizes the log marginal likelihood -
it does not need a validation split for kernel params. This is a real
advantage on small data.

================================================================================
9. GP VS BAYESIAN LINEAR VS CLASSICAL (COMPARISON)
================================================================================

                          Classical OLS   Bayesian lin. reg   GP
  Point prediction        yes             yes                yes
  Parameter uncertainty   via stats only  full posterior      implicit
  Prediction uncertainty  no (or naive)   yes (x^T S x)       yes (Sigma*)
  Uncertainty far from
    training data         no              grows (x^T S x)     grows (prior)
  Nonlinearity            manual feats    manual feats        via kernel
  n=10k+ scaling          great           great              poor (O(n^3))
  Interpretability        coefficients    distribution of coeff  black-box-ish

================================================================================
10. WHEN TO USE GPS (AND WHEN NOT)
================================================================================

USE GP when:
  - Small data (n < ~5k) where uncertainty matters and smoothness is a
    sane assumption (bayesian optimization, experimental design, sensor
    calibration, surrogate modeling)
  - You need calibrated uncertainty that grows out-of-distribution
  - Kernel structure matches your prior (periodicity, smoothness)

DO NOT USE when:
  - n >> 10k (use sparse approximations, random features, or NNs with
    ensembles/dropout for uncertainty)
  - High input dimension (>~20): kernel distance dilutes, GP flattens
  - You need a fast, simple deployable model: tree ensembles beat GP on
    most tabular data for point accuracy

Approximations if you must scale: sparse GP (inducing points),
random Fourier features (RFF) making GP = Bayesian linear regression in
feature space, or Nystroem approximation.

11. FAILURE MODES & DEBUGGING
================================================================================

Symptom                       Cause                          Fix
----------------------------- ----------------------------- ---------------------------
GP predicts prior mean (flat) far away  correct behavior!  add trend kernel / normalize
                                                          don't mistake for a bug
Uncertainty near zero everywhere       alpha too small +   increase alpha; check noise
                                       overfit noise
Lengthscale collapses (wiggly)        too few data /       constrain bounds,
                                       unlucky restart     more restarts
O(n^3) blowup                         data too large       sparse/RFF or reduce n
Predictions insensitive to data       lengthscale huge     rescale inputs to ~O(1);
                                       (inputs not scaled)  init length_scale sensibly
Numerical warnings (singular)         duplicate points     add jitter to alpha

Debugging check: predict with return_std=True on a grid INCLUDING
regions far outside training. The uncertainty envelope is the model's
honesty report - plot it every time.
