1. WHAT IS PROMPT ENGINEERING?
================================================================================

INTUITION
---------
The way you ask an LLM a question dramatically affects its response.
Prompt engineering is the skill of crafting inputs that get the
best outputs from language models.

"The difference between a mediocre and excellent LLM response
 is often the quality of the prompt."

================================================================================
2. PROMPT DESIGN PRINCIPLES
================================================================================

1. BE SPECIFIC: Vague prompts → vague answers
   BAD:  "Tell me about Python"
   GOOD: "Explain Python list comprehensions with 3 examples for beginners"

2. PROVIDE CONTEXT: Give background information
   GOOD: "You are a senior ML engineer. Explain X to a junior developer."

3. USE STRUCTURE: Organize your prompt clearly
   GOOD: Use sections, bullet points, numbered steps

4. SPECIFY FORMAT: Tell the model what output format you want
   GOOD: "Respond in JSON with keys: summary, key_points, action_items"

5. SET CONSTRAINTS: Define boundaries
   GOOD: "In exactly 3 bullet points, explain..."

================================================================================
3. PROMPTING TECHNIQUES
================================================================================

3.1 ZERO-SHOT PROMPTING
------------------------
Give the task without examples.

"Classify this review as positive or negative: 'The product is amazing!'"
→ The model relies on its pretraining knowledge.

3.2 FEW-SHOT PROMPTING
------------------------
Provide examples of input → output pairs.

"""
Classify reviews as positive or negative:

Review: "Great product!" → Positive
Review: "Terrible quality" → Negative
Review: "Love it so much" → Positive
Review: "Waste of money" →

Answer: Negative
"""

More examples → better performance, but costs more tokens.

3.3 CHAIN-OF-THOUGHT (CoT)
----------------------------
Ask the model to show its reasoning step by step.

BAD:  "What is 15% of 240?" → Model might guess
GOOD: "What is 15% of 240? Think step by step."

Model output:
1. 15% means 15/100 = 0.15
2. 0.15 × 240 = ?
3. 0.15 × 200 = 30, 0.15 × 40 = 6
4. 30 + 6 = 36
Answer: 36

3.4 ZERO-SHOT CHAIN-OF-THOUGHT
-------------------------------
Add "Let's think step by step" to zero-shot prompts.

3.5 SELF-CONSISTENCY
---------------------
Generate multiple CoT responses, take majority vote.
More robust but more expensive.

3.6 TREE OF THOUGHT
--------------------
Explore multiple reasoning paths, evaluate each, choose best.

3.7 REACT (Reasoning + Acting)
-------------------------------
Interleave reasoning with actions (tool calls).

Thought: I need to find the population of France
Action: search("population of France 2024")
Observation: 68 million
Thought: Now I can answer the question
Answer: The population of France is approximately 68 million.

================================================================================
4. SYSTEM PROMPTS
================================================================================

INTUITION
---------
System prompts set the LLM's role, behavior, and constraints.

SYSTEM PROMPT TEMPLATE
----------------------
"""
You are a senior data scientist with 10 years of experience.
You help junior developers understand ML concepts.

Rules:
1. Always explain the intuition before the math
2. Use concrete examples
3. Keep explanations under 200 words
4. If you don't know, say so
5. Never make up statistics or sources
"""

EXAMPLES
--------
# Medical assistant
system = "You are a medical information assistant. Provide general health info but always recommend consulting a doctor. Never diagnose."

# Code reviewer
system = "You are a senior code reviewer. Review code for bugs, performance issues, and style. Be constructive and specific."

# Technical writer
system = "You write clear technical documentation. Use simple language, short sentences, and include code examples."

5. PROMPT TEMPLATES
================================================================================

USING F-STRINGS
---------------
prompt = f"""
Analyze the following {data_type} data:
{data}

Provide:
1. Summary statistics
2. Key insights
3. Potential issues

Format your response as JSON.
"""

USING LANGCHAIN
---------------
from langchain.prompts import PromptTemplate

template = PromptTemplate(
    input_variables=["context", "question"],
    template="""
Answer the question based on the context below.
If the answer is not in the context, say "I don't have enough information."

Context: {context}

Question: {question}

Answer:"""
)

prompt = template.format(
    context="Python is a programming language...",
    question="What is Python?"
)

7. PROMPT OPTIMIZATION
================================================================================

ITERATION CYCLE
---------------
1. Write initial prompt
2. Test with 10-20 diverse inputs
3. Identify failure cases
4. Refine prompt
5. Repeat

COMMON ISSUES AND FIXES
-------------------------
Issue: Model ignores instructions
Fix: Put instructions at the END (recency bias) or use XML tags

Issue: Inconsistent format
Fix: Provide explicit format examples

Issue: Hallucination
Fix: Add "Only use information from the context" and reduce temperature

Issue: Too verbose
Fix: Add "Respond in exactly N sentences" or "Be concise"

================================================================================
8. COST OPTIMIZATION
================================================================================

STRATEGIES
----------
1. Shorter prompts → lower cost
2. Use smaller models (GPT-3.5) for simple tasks
3. Cache common queries
4. Batch similar requests
5. Use few-shot sparingly (each example = tokens)

TOKEN ESTIMATES
---------------
1 token ≈ 0.75 words (English)
1 token ≈ 4 characters
GPT-4 input: ~$0.03 per 1K tokens
GPT-4 output: ~$0.06 per 1K tokens

================================================================================
9. COMMON MISTAKES
================================================================================

MISTAKE 1: Overly complex prompts
  RIGHT: Simple, clear prompts usually work better

MISTAKE 2: Not testing edge cases
  RIGHT: Test with diverse inputs, not just happy path

MISTAKE 3: Hardcoding prompts in code
  RIGHT: Store prompts in config files, use version control

MISTAKE 4: Not using delimiters for content
  RIGHT: Use triple quotes, XML tags, or "###" to separate content

MISTAKE 5: Ignoring token limits
  RIGHT: Monitor token usage, truncate or chunk as needed
