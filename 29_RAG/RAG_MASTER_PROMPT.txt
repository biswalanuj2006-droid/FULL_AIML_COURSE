ROLE
================================================================================
Act as a PRINCIPAL AI/ML ENGINEER, RAG ARCHITECT, LLM RESEARCHER,
INFORMATION RETRIEVAL ENGINEER, and technical educator.

Produce an ULTRA-COMPREHENSIVE, INDUSTRY-GRADE, ENGINEERING-LEVEL course:
        COMPLETE RETRIEVAL-AUGMENTED GENERATION (RAG)
              FROM FUNDAMENTALS TO PRODUCTION

The course must NOT be a basic beginner tutorial. The student must be able to:
- understand the mathematics and theory behind RAG
- implement RAG systems from scratch
- use modern RAG frameworks (LangChain, LlamaIndex, LangGraph)
- understand every stage of the RAG pipeline
- debug retrieval failures
- evaluate retrieval quality
- optimize latency and cost
- build production-grade RAG applications
- design scalable RAG architectures
- build multimodal RAG, GraphRAG, agentic RAG
- understand advanced retrieval techniques
- deploy RAG systems
- explain RAG architecture in technical interviews
- design enterprise RAG systems

Do NOT skip difficult concepts. Do NOT reduce advanced topics into shallow
definitions. Use practical examples, mathematical intuition, diagrams,
pseudocode, Python implementations, experiments, failure cases, engineering
tradeoffs, and real-world architectures.

================================================================================
PART 1 - RAG FUNDAMENTALS
================================================================================
1. What is RAG? 2. Why RAG was invented. 3. Problems with vanilla LLMs.
4. Hallucination. 5. Knowledge cutoff. 6. Static model knowledge.
7. Private/proprietary data. 8. Domain-specific knowledge. 9. Grounded
generation. 10. RAG vs fine-tuning. 11. RAG vs prompt engineering.
12. RAG vs long-context LLMs. 13. RAG vs web search. 14. RAG vs traditional
information retrieval. 15. RAG vs knowledge graphs. 16. RAG vs agents.

RAG lifecycle (explain EVERY stage independently):
USER QUERY -> QUERY PROCESSING -> QUERY TRANSFORMATION -> RETRIEVAL ->
FILTERING -> RERANKING -> CONTEXT CONSTRUCTION -> PROMPT CONSTRUCTION ->
LLM GENERATION -> POST-PROCESSING -> CITATIONS/SOURCES -> FINAL RESPONSE

================================================================================
PART 2 - COMPLETE RAG PIPELINE
================================================================================
Ingestion: Documents -> Document Loading -> Parsing -> Cleaning ->
Normalization -> Metadata Extraction -> Document Classification -> Chunking ->
Embedding -> Vector Storage -> Indexing.

Query pipeline: User Query -> Query Analysis -> Query Rewriting -> Query
Expansion -> Embedding -> Candidate Retrieval -> Hybrid Retrieval ->
Filtering -> Reranking -> Context Compression -> Context Assembly -> Prompt ->
LLM -> Grounded Answer -> Citation.  Explain each component deeply.

================================================================================
PART 3 - DOCUMENT INGESTION
================================================================================
Formats: PDFs, DOCX, TXT, Markdown, HTML, CSV, JSON, XML, Excel, PowerPoint,
webpages, emails, databases, APIs, cloud storage, Git repositories, source
code, images, scanned documents.
Concepts: loaders, parsers, OCR, document normalization, metadata extraction,
duplicate detection, document versioning, document IDs, source tracking,
timestamps, access-control metadata.
WHY: bad ingestion creates bad RAG.

================================================================================
PART 4 - DOCUMENT PARSING
================================================================================
PDF parsing, layout-aware parsing, table extraction, image extraction, OCR,
headers/footers/page numbers, hyperlinks, citations, code extraction,
structured documents. Tools: PyMuPDF, pdfplumber, Unstructured, Apache Tika,
OCR systems, document intelligence systems. Parser failure modes.

================================================================================
PART 5 - CHUNKING
================================================================================
Types: fixed-size, character, token, sentence, paragraph, recursive,
semantic, hierarchical, document-aware, structure-aware, markdown, code,
table chunking.
Explain: chunk size, chunk overlap, token limits, semantic boundaries,
context preservation, retrieval granularity. Discuss 128/256/512/1024-token
chunks and large vs small chunks. Tradeoffs. Experiments: small vs medium vs
large chunks. Chunking failure modes.

================================================================================
PART 6 - EMBEDDINGS
================================================================================
First principles: vectors, dimensions, semantic representation, embedding
space, semantic similarity, cosine similarity, dot product, Euclidean
distance, normalization. Mathematics of each. Embedding models; sentence /
document / query / multilingual / domain-specific / code embeddings.
Concepts: embedding dimension, vector normalization, embedding drift, model
selection, multilingual retrieval, domain adaptation. Practical Python.

================================================================================
PART 7 - VECTOR DATABASES
================================================================================
FAISS, Chroma, Qdrant, Weaviate, Milvus, Pinecone, Elasticsearch/OpenSearch
vector search, pgvector. Concepts: collections, indexes, vectors, metadata,
payloads, namespaces, filtering, persistence, sharding, replication.

================================================================================
PART 8 - VECTOR INDEXING (ANN)
================================================================================
Brute force vs exact vs approximate nearest neighbor. HNSW (graph
construction, layers, M, efConstruction, efSearch), IVF, PQ, IVF-PQ, Annoy,
ScaNN. Recall vs latency tradeoffs.

================================================================================
PART 9 - RETRIEVAL
================================================================================
Semantic / lexical / keyword / dense / sparse / metadata retrieval.
Top-K: K=1,3,5,10,20,50. Why increasing K does not always improve answers.

================================================================================
PART 10 - BM25
================================================================================
From first principles: term frequency, inverse document frequency, document
length normalization, k1, b. Full formula. Python implementation. BM25 vs
dense embeddings.

================================================================================
PART 11 - HYBRID SEARCH
================================================================================
Dense + sparse -> hybrid. BM25 + embeddings, reciprocal rank fusion (RRF
mathematics), weighted fusion, score normalization, rank fusion. When hybrid
beats pure vector search. Practical implementation.

================================================================================
PART 12 - METADATA FILTERING
================================================================================
Date/category/user/permission/tenant/document-type/source filters. Semantic
retrieval + metadata filtering. Enterprise access-control RAG.

================================================================================
PART 13 - QUERY TRANSFORMATION
================================================================================
Query rewriting, expansion, decomposition, classification, normalization,
spelling correction, synonym expansion, intent detection. Advanced: HyDE,
multi-query retrieval, step-back prompting, sub-question generation, query
routing.

================================================================================
PART 14 - HYDE
================================================================================
QUERY -> LLM generates hypothetical answer/document -> Embedding -> Vector
search -> Retrieved documents -> Final LLM. Why HyDE can improve retrieval.
Its risks.

================================================================================
PART 15 - MULTI-QUERY RETRIEVAL
================================================================================
One query -> generate variations -> retrieve each -> merge -> rerank ->
generate. Query diversity, redundancy, latency, cost.

================================================================================
PART 16 - QUERY DECOMPOSITION
================================================================================
Complex questions -> sub-questions -> multi-step retrieval. Example:
"What were Apple's revenues and profit margins from 2020 to 2025?" broken into
per-year revenue + margin calculations.

================================================================================
PART 17 - RERANKING
================================================================================
Why first-stage retrieval is not enough. Vector search -> Top 50 -> Reranker
-> Top 5 -> LLM. Cross-encoders, bi-encoders, rerankers, relevance scoring,
late interaction. BGE reranker, Cohere rerank. Latency vs quality.

================================================================================
PART 18 - CONTEXT ENGINEERING
================================================================================
Context selection, compression, ordering, redundancy removal, prioritization,
lost-in-the-middle problem, context windows, token budgets. Why MORE context
can produce WORSE answers.

================================================================================
PART 19 - PROMPT ENGINEERING FOR RAG
================================================================================
System prompts, context instructions, source attribution, citation
requirements, refusal behavior, grounding constraints, answer formatting,
uncertainty handling. Professional RAG prompt templates.

================================================================================
PART 20 - LLM PARAMETERS
================================================================================
temperature, top_p, top_k, max_tokens, stop sequences, frequency penalty,
presence penalty, repetition penalty, seed, reasoning parameters.
TEMPERATURE deep-dive: T=0, 0.1, 0.3, 0.5, 0.7, 1.0, >1 mathematically via
P(token) = softmax(logits / temperature). Effect on determinism, creativity,
factuality, hallucination, diversity, RAG reliability.
CRITICAL: temperature controls GENERATION, not retrieval. Retrieval params
(top_k, similarity threshold, efSearch, reranking depth, candidate count) are
separate.

================================================================================
PART 21 - TOP-P
================================================================================
Nucleus sampling. top_p = 0.1 / 0.5 / 0.9 / 1.0. Compare temperature vs top_p.

================================================================================
PART 22 - RAG GENERATION STRATEGIES
================================================================================
Extractive vs abstractive RAG, grounded generation, citation generation,
quote-based answers, answer synthesis, multi-document synthesis.

================================================================================
PART 23 - HALLUCINATION
================================================================================

retrieval, reranking, grounding prompts, citations, confidence estimation,

metric explained mathematically.
