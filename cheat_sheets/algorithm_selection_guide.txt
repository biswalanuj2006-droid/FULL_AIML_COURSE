ALGORITHM SELECTION GUIDE - WHICH MODEL WHEN?
Reference card. For every case: pick primary, justify, list alternatives.

HOW TO USE THIS CARD
1. Define the task: regression / binary / multiclass / clustering /
   anomaly / ranking.
2. Define the constraints: n, d, latency, interpretability, label
   availability, data type.
3. Read the matching row below, then sanity-check with the
   "default ladder".

================================================================================
DEFAULT LADDERS (when nothing special is true)
================================================================================
Tabular regression, clean, n<100k:
   Linear/Ridge baseline -> Gradient Boosting (or RF if you need
   speed/robustness) -> tune -> done.
Tabular classification, clean, n<100k:
   Logistic baseline -> Gradient Boosting (LightGBM/XGBoost/CatBoost)
   -> tune -> done. Check calibration if probabilities are used.
Small data (n<1k):
   Regularized linear, KNN, or a shallow tree; GP if you need
   uncertainty. Avoid deep nets (they need data or pretraining).
Images: CNN (pretrained, fine-tune). Text: transformer or TF-IDF+
   linear. Sequences: LSTM/Transformer per module 21/26.
Unsupervised structure: K-Means (blobs) -> DBSCAN/HDBSCAN (density)
   -> GMM (soft/probabilistic). Dim reduction: PCA first, t-SNE/UMAP
   for visualization only.
Anomaly: Isolation Forest default -> LOF for local density ->
   Elliptic Envelope for Gaussian -> autoencoder for images/sequences.

================================================================================
COMPLEXITY QUICK REFERENCE (typical; training, prediction)
================================================================================
Linear regression (normal eq):  O(n d^2 + d^3), O(d)
Ridge/Lasso (coord. descent):   ~O(n d) per pass, O(d)
Logistic regression (GD):       O(n d) per epoch, O(d)
KNN (brute force):              O(1) store, O(n d) predict  (k-d tree ~O(log n) low-d)
Naive Bayes:                    O(n d) train, O(c d) predict
Decision tree (CART):           O(n d log n)-ish, O(depth)
Random Forest:                   trees x single tree; predict O(T x depth)
Gradient boosting:               M x O(n d log n); predict O(M x depth)
XGBoost/LightGBM:                histogram bins speed train; predict like GB
SVM (kernel, SMO-like):          between O(n^2) and O(n^3) train, O(n_SV x d) predict
K-Means:                         O(n k d) per iteration, O(k d) predict
DBSCAN:                          O(n log n) with index (O(n^2) brute), O(1)
Gaussian Process:                O(n^3) train, O(n^2) predict
Neural net (per epoch):          O(n x params); predict O(params)
Isolation Forest:                O(trees x n log n)-ish train, O(trees x depth)

Rules of thumb:
  - Trees/GB: excel tabular, non-linear, mixed dtypes, n<1M.
  - Linear: fast, interpretable, scales to huge sparse data, needs
    feature work + scaling.
  - Kernel SVM: great small-to-medium n; do not use for n>50k.
  - Deep nets: need data/pretraining; win images/text/audio.
  - GP: n<5k, uncertainty, smooth functions.
  - If two models tie on validation, deploy the simpler/faster one.

9. 1M images, 1000 classes (with and without GPU budget).

11. Time series with strong seasonality and known holidays.
12. Clusters with different densities + noise (customer types).

14. Anomaly detection on 5,000 servers x 200 metrics.
